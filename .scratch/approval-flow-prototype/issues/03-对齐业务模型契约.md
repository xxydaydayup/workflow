# 03: 对齐立项审批业务模型契约

Type: task
Blocked by: None
Status: resolved

**What to build:** 让前后端对立项审批使用同一份业务模型契约，明确 `project_approval_json` 中节点和连线如何表达业务步骤、审批结果及去向。

- [x] 明确顶层节点、连线字段和稳定节点标识；会签是独立的 `countersign` 节点，固定采用 `approveMode: ALL`。
- [x] 明确普通审批结果通过其后的条件分支和 `pass` / `reject` 路径表达；驳回回到申请填写步骤。
- [x] 设计 DTO 不包含表单 schema、审批人值或 Camunda 变量名；固定表单与启动审批人字段说明由业务系统和后端提供。
- [x] 记录业务模型转换与流程发布分开的接口边界。用户确认现有 `/v1/bpmn/json2xml` 承担业务模型转换，后端后续改造此接口。
- [x] 提供覆盖通过、驳回回流和会签结论的立项审批 JSON 示例。

## Answer

已将立项审批样例契约记录在[业务模型文档](../../../docs/examples/立项申请/project_approval_json.md)，并更新 GLOSSARY 与 ADR-0001。普通审批和会签分别为 `approval`、`countersign`；会签 `approveMode` 固定为 `ALL`。申请填写步骤按图结构识别：流程完整后是审批结果 `reject` 连线目标，编辑未完成时是开始节点后直接连接的首个 `approval`；无需新增用途字段或依赖固定节点 ID。用户确认现有 `/v1/bpmn/json2xml` 承担业务模型转换，编译与发布分开处理；真实转换结果见 issue 02。

工作区原有 `.scratch/approval-flow-prototype/issues/02-业务模型编译契约.md` 曾描述请假场景和旧业务模型；现已将其当前验收范围收敛为立项契约编译验证，历史请假方案仅保留为 superseded 记录。

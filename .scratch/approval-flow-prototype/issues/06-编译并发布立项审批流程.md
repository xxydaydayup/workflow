**What to build:** 让流程设计者把检查通过的业务模型交给后端编译，并通过独立的发布操作生成可启动的立项审批版本。界面清楚区分“编译业务模型”和“发布流程”，显示后端校验、编译或发布错误，以及发布成功后可供后续启动使用的流程信息。

- [x] 调用约定的业务模型编译接口 `/v1/bpmn/json2xml`；前端直接发送 `project_approval_json`，不在前端生成 BPMN 或 Camunda 配置。
- [x] 编译成功后通过独立发布接口发布流程；编译错误显示后端响应（节点/连线定位待后端提供）。
- [x] 发布成功后展示任务模板标识、版本、部署/流程定义标识及启动字段说明。
- [x] 独立 taskKey 发布返回 v1；Swagger 明确同一 (tenant, taskKey) 会覆盖唯一的当前业务模板记录，Camunda 流程定义另存版本历史。独立 taskKey 二次发布实测返回 v2，旧运行任务仍绑定 v1 的流程定义 ID。未覆盖共享 project-approval 模板。

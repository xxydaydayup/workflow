# 05: 检查审批路径并定位问题

Type: task
Blocked by: 04: 实现三栏流程设计器
Status: resolved

**What to build:** 让流程设计者在画完流程后检查业务模型结构，快速发现缺失或无效路径，并从检查结果直接跳到画布上的问题节点或连线。前端检查提供即时反馈，流程是否可编译和发布仍由后端最终校验。

- [x] 检查流程恰有一个开始节点和结束节点，节点名称有效，必要节点之间存在连线。
- [x] 检查所有步骤均可从开始节点到达，并存在通往结束节点的路径；报告孤立节点、断开的连线和无法完成的路径。
- [x] 检查审批节点按契约连接结果条件节点，结果节点具有且仅具有所需的通过与驳回路径。
- [x] 检查驳回路径回到立项申请填写步骤；会签按 ALL 约定继续到审批结果分支。
- [x] 检查结果列表展示可理解的业务说明；点击检查项可选中并定位到对应节点或连线。
- [x] 流程结构有效时显示通过状态；编辑流程后及时更新检查状态，避免继续展示过期结果。

## Answer

检查逻辑覆盖开始/结束数量、节点名称、孤立与断开路径、可达性、完成路径、审批结果分支、申请填写回路、开始入口和固定 ALL 会签路径。问题列表显示具体节点或“起点 → 终点”位置；点击问题项会选中对应节点/连线并适配画布视野。若问题同时关联连线与节点，连线属性选中且视野包含相关节点。流程变化后清除已检查状态，避免展示过期结论。

新增拓扑和定位元数据单测；验证 `pnpm typecheck`、`pnpm test`（完成时 36 项；2026-10-23 后端变量元数据测试加入后总数 37 项）、`pnpm lint`、`pnpm build`，并用 agent-browser 检查结构通过状态与无效孤立节点问题定位。前端结构检查不代替后端编译和发布校验。

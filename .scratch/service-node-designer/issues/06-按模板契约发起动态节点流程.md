# 06: 按模板契约发起动态节点流程

Type: task
Blocked by: 01, 02
Status: 后续范围；保留已有启动页，服务运行验证待隔离模板

## What to build

让流程发起方按已发布模板提供动态服务地址和会签设置，使模板未固化的节点参数可在启动实例时输入；已固化的配置不要求重复提供或被输入覆盖。

- [x] 按已查回的模板 `globalVariables` 元数据及 `{nodeId}_serviceName` / `{nodeId}_serviceUrl` 变量生成动态服务字段；固定字段不要求重填，服务地址校验 HTTP(S)。升级前最后读取的 Swagger schema 未列出 `service` 字段，后端文档差异记在 issue 01。
- [x] 对模板未固化会签模式的节点按 `{节点id}_approveMode` 显示发起输入，未填写时使用 `ALL`；模板元数据提供 `allowed` 时显示对应选项，未提供时允许输入后端支持的模式，避免前端枚举阻止未来新增值。
- [x] 节点 `approveMode` 与启动变量区分：节点配置值属于 `nodes[]`，仅模板未固化模式时才可按节点 ID 派生启动变量；`allowed` 是字段可取值元数据。当前动态模式字面值尚未由后端公布，不能预设第四种值。
- [x] 对模板未提供的 `passRate` 显示按节点 ID 派生的输入并校验 `(0, 1]`；模板级 VOTE 缺少比例时阻止启动。
- [x] 会签字段从通用字段列表中分离，防止重复展示；启动变量重复输入、越过 allowed 的选项或无效比例时阻止请求并保留输入。
- [x] 当启动变量元数据公开 `allowed` 时，下拉选项由该列表驱动；未公开 `allowed` 时使用文本输入，支持后端契约实际公布的值。该下拉的 `allowed` 描述属性值，不作为请求参数名。节点配置字段保留开放字符串；当前编译器仍只接受 `ALL` / `ANY` / `VOTE`。
- [x] 启动失败提示会移除符合 URL 长度的原始和编码输入值；启动页面可从模板元数据生成开放字段。
- [x] 用两个独立 templateKey 在后端发布并查回隔离模板：固定 serviceName + 动态 serviceUrl，以及两者均动态；globalVariables 正确区分 engine/start 来源并公开必填标记。浏览器确认动态模式、比例、服务名、服务 URL 输入。此验证基于升级前的 Swagger 与后端。
- [ ] 对隔离实例验证 worker 执行与安全目标策略；误触发起的实例已按业务编号删除并转为 `FAILED`，模板业务记录也已删除。未确认 worker 是否访问了输入 URL。
- [x] 浏览器验证当前模板与隔离模板的变量字段、动态会签选择、比例和动态服务输入；误触发的实例未重试。

## Answer

会签和服务启动表单按模板元数据生成；`allowed` 是值列表，参数名取变量 `name`，而 `nodes[].approveMode` 是业务模型中的节点属性。Swagger 路径已于 2026-10-28 复核仍与代码一致，`/bpmn/spec` 的当前模式列表是 `ALL` / `ANY` / `VOTE`。一次误触实例的 worker 外呼情况仍未知，须查后端日志与网络策略后才能做运行验收。

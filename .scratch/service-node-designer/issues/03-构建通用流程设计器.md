# 03: 构建通用流程设计器

Type: task
Blocked by: 02
Status: 可由智能体处理

## What to build

将默认流程设计入口收敛为由当前业务模型驱动的通用设计器，让流程设计者可拖放节点、编辑节点与路径并生成业务 JSON，不再强制初始化或验证立项审批拓扑。

- [ ] 节点库为业务管理员提供当前已支持的通用节点，包括 `start`、`approval`、`condition`、`countersign`、`service`、`end`。
- [ ] 支持从节点库拖放或添加节点、移动节点、创建和重连路径；开始和结束节点数量约束按已确认模型规则检查。
- [ ] 选中服务节点时属性面板可配置名称、`serviceName`（按 issue 01 的结果）和服务地址。
- [ ] 服务地址为空时显示动态地址模式，非空时显示固定地址模式，并清楚提示动态地址在流程发起时提供。
- [ ] 通用流程名称、标识、节点和画布坐标从当前编辑内容生成；节点改名或移动不破坏节点标识和路径。
- [ ] 现有基于立项流程的审批填写拓扑和变量假设不得作为所有流程的强制规则；通用结构检查只校验适用于全体流程的结构及经确认的节点约束。
- [ ] 预览或下载时生成符合业务模型契约的 JSON，且动态与固定服务样例字段符合 issue 02 契约。
- [ ] 通过浏览器实际操作完成拖放、路径编辑、属性修改、坐标移动和 JSON 导出验证；按仓库约定不得新建测试文件。

## Prototype reference

初版布局方案和交互请查看分支 `codex/service-node-designer-prototype`：`/designer?variant=prototype-a`（三栏属性面板）、`prototype-b`（画布优先、右侧编辑）、`prototype-c`（全景画布、底部属性舱）。三稿共享库存校验服务节点和动态/固定地址 JSON 预览。该分支只作设计探索，选择方案后再将决策融入正式实现。

## What to build

扩展前后端共享的业务模型，使其完整表达通用流程、服务节点和可按模板或实例控制的会签规则，同时保留模型现有的流程、节点及路径结构。

- [x] 业务节点类型支持 `service` 和可选 `serviceName`/`serviceUrl`，动态与固定值能分别表达。
- [x] `countersign` 保留开放字符串 `approveMode` 和可选 `passRate`；不把 DTO 限制到当前三种模式。
- [x] 模型保留 `processId`、`processName`、`nodes`、`flows` 以及 `source`、`target`、可选 `branch`，不暴露 BPMN/Camunda 属性。
- [x] 浏览器 JSON 预览核对固定服务名、动态服务地址和普通会签字段；编译接口已接收带 service/countersign/condition/reject 回流的模型。

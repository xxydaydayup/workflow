# 01: 明确服务与会签节点契约

Type: research
Blocked by: None
Status: API 路径已复核；服务运行安全与端到端环境待补充

## What to resolve

将服务节点与动态会签规则对齐到后端编译、模板元数据、实例启动和运行能力，形成后续业务模型与界面共同遵循的契约。业务模型仍保持 `processId`、`processName`、`nodes`、`flows` 结构，由后端负责编译为流程定义。

- [x] 上一次 Swagger 可访问时确认模板读写路径为 `/api/v1/template`，实例启动为 `/api/v1/task/instances/start`，业务模型编译为 `/api/v1/bpmn/json2xml`；模板 multipart 使用 `template-key`/`template-name`，实例请求使用 `templateKey`。当时模板发布不接收 `version`，由后端维护版本；该基线待本次 Camunda 升级后重新核对。旧 `/api/v1/task/deployments` 路径当时不存在。
- [x] 上一次可访问的 Swagger 确认会签字段 `approveMode`/`passRate`：模板有值时固化，未填时从 `{节点id}_approveMode` / `{节点id}_passRate` 启动变量传入，模式缺省 `ALL`；`passRate` 范围 `(0,1]`，模板级 VOTE 必须有通过比例。升级后的字段规则待重核。
- [x] 上一次可访问的 Swagger 将 `approveMode` 文档化为 `ALL`、`ANY`、`VOTE`，其他值 Java 侧报错；`BpmnJSONNode` 的 type 描述也未列 `service`。该版 Swagger 节点 schema 没有 `serviceName`、`serviceUrl` 字段，模板 `globalVariables` 仅有 `name/type/description/source/required/value`，没有 `allowed`；Camunda 升级后的契约需重新读取。
- [x] 上次可达时通过本机 Vite 代理对只读编译端点做最小探测：包含 `type=service`、`serviceName`、`serviceUrl` 的 JSON 被接受，成功返回 2640 字符 BPMN XML，产物包含服务主题及 `example.invalid` 地址。由此确认当时编译器接受服务字段，但 Swagger 未同步其契约。探测只调用编译端点，没有部署或启动流程。
- [x] 上次可达时只读编译请求中的未知会签值 `FOURTH_MODE` 未被后端接受，Camunda 返回 HTTP 500 并由网关包装为 `INTERNAL_ERROR`。这与当时 Swagger 的“不支持其他值”描述相符，但错误并非结构化的参数校验响应；本探测没有部署或启动流程。升级后尚未复验。
- [x] 只读读取 `/api/v1/template/project-approval` 成功，确认当时响应模板为第 5 版，`globalVariables` 含 `{nodeId}_approveMode`、`{nodeId}_passRate` 字段；该响应未返回 `allowed`。旧 `/api/v1/task/deployments` 经代理返回 404。
- [x] 上一次核对模板发布 OpenAPI multipart 参数没有 `version`；当时版本号由后端维护，前端发布请求不再发送该字段。升级后的发布字段与版本规则待重核。
- [x] 2026-10-28 再次读取 Swagger `http://192.168.124.202:9000/swagger/doc.json`：确认模板 `/api/v1/template`（multipart 的 `template-key`、`template-name` 等字段）、模板详情 `/api/v1/template/{key}`、实例启动 `/api/v1/task/instances/start` 和编译 `/api/v1/bpmn/json2xml` 仍与当前调用路径一致。未调用发布或启动接口。Swagger 的 `BpmnJSONNode` 仍未列出 `service`/`serviceName`/`serviceUrl`，而 `/bpmn/spec` 明确列出并且本轮只读编译验证接受它们；本项目的业务模型实现契约以 `/bpmn/spec` 和编译行为为准，Swagger 描述缺口继续向后端反馈。

## Answer

2026-10-28 复核后，Swagger 路径及模板/启动参数与代码一致。最新 `/bpmn/spec` 定义 `nodes[].approveMode` 是节点字段，`allowed` 是字段可取值元数据，不是另一个传参字段；节点未固化模式时的运行时变量名才是 `{nodeId}_approveMode`（如 `managers_approveMode`）。当前已公布并由编译器接受的取值为 `ALL`、`ANY`、`VOTE`，`FOURTH_MODE` 只读编译仍返回 500；未来值须以后续契约更新为准，前端不得预造。`/bpmn/spec` 明确支持 service 节点、直接审批/会签/服务分支、condition 上游规则与 conditionExpression；Swagger schema 对 service 字段仍有遗漏。真实 worker 执行、动态地址安全策略、隔离成功/失败运行及误触实例是否外呼仍无证据，需后端日志与隔离环境确认。

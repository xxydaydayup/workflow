# 03: 按业务模型编辑并导出通用流程

Type: task
Blocked by: 02
Status: 已完成

## What to build

让已选定的 prototype-a 以当前流程业务模型驱动画布，使流程设计者能编辑通用流程并导出符合契约的业务 JSON。prototype-a 保持为开发验证入口直至 #05 收敛正式路由。采用单画布所需的轻量状态与节点定义组织方式，节点默认值、节点展示元数据、画布映射和编辑操作有清楚的维护位置；不引入多画布 store、复杂通用节点基座或每节点完整五件套。

- [x] prototype-a 的三栏交互能够编辑流程名称和标识，并添加、拖动、选择、删除支持的节点；正式路由已由 #05 切换。
- [x] 节点库覆盖当前业务模型契约支持的 `start`、`approval`、`countersign`、`service`、`condition`、`end` 类型；开始和结束节点按契约约束数量。
- [x] 统一属性面板按选中节点编辑名称和当前已纳入的业务属性：通用 `form`、审批办理人、提醒、会签顺序/模式/比例、服务名称和地址，以及连线分支/显式条件表达式。会签 `approveMode` 的 UI 只提供当前契约值 `ALL`/`ANY`/`VOTE`，字段在业务 DTO 中保持开放字符串；未来值由新契约支持后再接入。
- [x] 创建、删除、重连和编辑节点/连线后，节点标识、坐标和路径引用保持一致；画布适配不会把 React Flow 专属字段写进业务模型。
- [x] 业务 JSON 预览与下载反映当前编辑数据，字段结构遵从 issue 02；动态服务地址省略时按记录的契约处理。
- [x] 浏览器验证正式 `/designer` 的节点库、会签和提醒属性、通过比例及 JSON 预览；确认 `countersign` 输出 `sequential`、reminder、`approveMode` 和 `passRate`，并保留原有流程坐标和 pass/reject 连线。
- [x] 当前范围将正式设计器收敛为编辑、基础检查及业务 JSON 预览/下载；编译、发布和实例发起后续按需完善。

## Answer

prototype-a 已映射至通用业务模型，可编辑流程、节点和路径、检查结构并预览/下载 JSON。当前范围暂不包含编译、发布和实例发起。浏览器确认会签/提醒字段输出和原流程语义、坐标保留；后续编译/运行验收按 issue 07 处理。
